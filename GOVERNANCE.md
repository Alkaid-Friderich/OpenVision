# Governance

OpenVision currently uses a founder-led, transparent governance model while the first specification and reference implementation are established.

## Decision making

- Routine implementation decisions are made through reviewed pull requests.
- Material changes to project scope, the OVX format, compatibility, privacy, or provenance should begin with a public proposal.
- Decisions should record alternatives, trade-offs, and dissent where relevant.
- Maintainers may reject contributions that conflict with the project's ethics or safety principles even when technically sound.

## Roles

- **Contributors** submit issues, research, designs, code, tests, or documentation.
- **Reviewers** provide sustained, constructive review in a project area.
- **Maintainers** merge changes, manage releases, and uphold project policy.

The process for appointing maintainers and resolving formal disputes will be expanded before the first stable release.
