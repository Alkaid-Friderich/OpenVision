# Contributing to OpenVision

OpenVision is at an early design stage. Clear problem statements, small prototypes, reproducible experiments, and critical review are especially valuable.

## Before contributing

1. Read the project vision, ethics principles, and current roadmap.
2. Search existing issues and discussions before starting substantial work.
3. Open an issue for changes to the OVX format, architecture, privacy model, or project scope.

## Pull requests

- Keep each pull request focused on one coherent change.
- Explain the motivation, user impact, and validation performed.
- Add or update tests and documentation when behavior changes.
- Do not commit private recordings, credentials, generated build output, or data without explicit redistribution rights.
- Label reconstructed, inferred, and generated visual material accurately.

## Commit messages

Use short, imperative summaries such as `Define OVX timing model` or `Add WebXR pose playback`.

## Developer certificate of origin

By contributing, you certify that you have the right to submit the contribution under the repository's license. A formal DCO sign-off process may be introduced as the community grows.
